# Hinweise, Korrekturen und Beiträge

Die Seite stellt einen Debattenvorschlag zur Verfügung, **keine betreute Kampagne**. Sachliche Korrekturhinweise sind willkommen. Es gibt keine zugesagte Bearbeitungsfrist.

## Einen Fehler melden

Falls GitHub Issues aktiviert sind, im Repository ein Issue eröffnen. Hilfreich sind:

1. Die betroffene Seite und die genaue Textstelle.
2. Der überprüfbare Fehler oder fehlende Kontext.
3. Ein Link auf die Primärquelle mit Datum und, wenn möglich, Fundstelle.
4. Eine vorgeschlagene präzise Formulierung.

Bitte **keine** Anschriften, privaten Telefonnummern, unveröffentlichten Chats oder anderen Daten unbeteiligter Personen posten. Ein politischer Widerspruch ist nicht automatisch ein Tatsachenfehler; er kann trotzdem als Gegenargument wertvoll sein.

## Änderungen nachvollziehen

Inhaltliche Korrekturen werden in `CHANGELOG.md` und auf `updates.html` notiert. Die Git-Commit-Historie zeigt die technische Änderung. Für PDFs gilt: Verweis auf die betroffene Fassung und ihr Stichtagsdatum hinzufügen, statt eine Aussage stillschweigend zu ersetzen.

## Nutzung der Fragen

Die Fragen sind als allgemeines Gesprächswerkzeug formuliert und können zitiert, angepasst und an alle Parteien gerichtet werden. Die PDFs enthalten auch Zitate und Verweise auf Materialien Dritter; aus diesem Repository wird **keine pauschale Lizenz** für solche Fremdinhalte abgeleitet.
